# Вычисление поля `format`

Поле `format` в выходном JSON вычисляется по значениям из Leader MARC-записи:

- `Leader/06` — тип записи (`typeOfRecord`);
- `Leader/07` — библиографический уровень (`bibliographicLevel`).

Исходный MARC-файл не содержит отдельного поля `format`. Значение добавляется при преобразовании записи в JSON.

## Соответствие MARC 21

По правилам MARC 21 формат определяется следующим образом:

| `Leader/06` | `Leader/07` | `format` | Тип материала |
|---|---|---|---|
| `a` | `a`, `c`, `d`, `m` | `BK` | книги и другие монографические текстовые материалы |
| `a` | `b`, `i`, `s` | `CR` | продолжающиеся ресурсы |
| `t` | любое допустимое значение | `BK` | рукописные текстовые материалы |
| `c`, `d`, `i`, `j` | — | `MU` | музыка и звукозаписи |
| `e`, `f` | — | `MP` | картографические материалы |
| `g`, `k`, `o`, `r` | — | `VM` | визуальные материалы, комплекты и трёхмерные объекты |
| `m` | — | `CF` | компьютерные файлы |
| `p` | — | `MX` | смешанные материалы |

Официальные источники:

- [MARC 21 Format for Bibliographic Data — Leader](https://www.loc.gov/marc/bibliographic/bdleader.html)
- [MARC 21 Format for Bibliographic Data — Introduction](https://www.loc.gov/marc/bibliographic/bdintro.html)
- [MARC 21 field 008](https://www.loc.gov/marc/bibliographic/bd008.html)

## Порядок вычисления в текущей реализации

Функция `resolveFormat()` выполняет проверки последовательно:

1. Если `Leader/06 = a`, а `Leader/07` равен `b`, `i` или `s`, возвращается `CR`.
2. Если `Leader/06` равен `a` или `t`, возвращается `BK`.
3. Для `Leader/06 = e` или `f` возвращается `MP`.
4. Для `Leader/06 = c`, `d`, `i` или `j` возвращается `MU`.
5. Для `Leader/06 = g`, `k`, `o` или `r` возвращается `VM`.
6. Для `Leader/06 = m` возвращается `CF`.
7. Для любого другого значения возвращается `MX`.

Проверка `CR` должна выполняться раньше проверки `BK`, поскольку обе категории могут иметь `Leader/06 = a`.

## Пример

Leader:

```text
01590cam a2200217 u 4500
```

Значимые позиции:

```text
Leader/06 = a
Leader/07 = m
```

Результат:

```json
{
  "format": "BK"
}
```

Такой результат подтверждён эталонной парой файлов:

- `docs/015316815/015316815.mrc`;
- `docs/015316815/015316815.json`.

В `docs/010492547.json` также указано сочетание `Leader/06 = a`, `Leader/07 = m` и `format = BK`, но соответствующего исходного MARC-файла для этого JSON в проекте нет.

## Ограничения текущей реализации

Текущий алгоритм шире официального соответствия MARC 21:

- при `Leader/06 = a` любое значение `Leader/07`, кроме `b`, `i` и `s`, превращается в `BK`, хотя стандарт явно относит к `BK` значения `a`, `c`, `d` и `m`;
- любое неизвестное значение `Leader/06` превращается в `MX`, хотя по стандарту `MX` соответствует конкретному значению `p`;
- валидатор пока не проверяет допустимость `Leader/06` и `Leader/07`.

Поэтому локальными JSON-образцами сейчас подтверждено только соответствие `a + m → BK`. Остальные варианты основаны на спецификации MARC 21 и требуют отдельных тестов.
