# Источник поля `format` в профиле РГБ

В профиле РГБ верхнеуровневое поле MARC-JSON `format` берётся из служебного
поля Aleph `FMT`, а не вычисляется из Leader. При обратном преобразовании
`format` снова записывается в `FMT`.

Источник требования — `DevRGB-170826-1001-43.pdf`:

- стр. 84: перечислены служебные поля Aleph, в том числе `FMT` — формат
  библиографической записи;
- стр. 28–29: приведено стандартное соответствие Leader/06 и Leader/07
  форматам MARC 21. Эта таблица объясняет стандартный MARC 21, но не заменяет
  служебное поле `FMT` в профиле РГБ;
- стр. 17–19: описана кастомизированная схема РГБ и её отличия от исходных
  MARC-схем.

## ISO 2709 → MARC-JSON

1. Парсер ищет поле с тегом `FMT` без учёта регистра.
2. `FMT` разбирается как служебное контрольное поле: у него нет индикаторов и
   подполей.
3. Допустимы `AN`, `AU`, `BK`, `CF`, `CR`, `MP`, `MU`, `MX`, `SE`, `VM`.
   Коды `AN`, `AU` и `SE` добавлены после проверки реальных выгрузок
   `rsl06`, `rsl07`, `rsl10`; в частности, нормативная база `rsl10`
   преимущественно использует `AU`.
4. Само `FMT` не включается в массив `fields`, потому что его значение уже
   представлено верхнеуровневым свойством `format`.
5. Если `FMT` отсутствует, повреждено или не содержит единственного
   распознаваемого кода, результат равен `"<unrecognized>"`. Подстановки по
   Leader нет.

Последнее правило намеренное: иначе повреждение или отсутствие служебных
данных было бы незаметно, а результат мог бы расходиться с форматом,
назначенным в Aleph.

## MARC-JSON → ISO 2709 или Aleph sequential

Поле `format` обязательно и должно содержать один из десяти кодов. Имя JSON
задаёт целевой контейнер: `.iso.json` — ISO 2709, `.aleph.json` — Aleph
sequential. Оба сериализатора создают служебное поле `FMT` первым. Передавать
ещё одно `FMT` внутри `fields` запрещено, чтобы не получить два источника
истины.

Позиции Leader/00–04 и Leader/12–16 при этом пересчитываются, поэтому Leader
после круглого преобразования не обязан побайтно совпасть с исходной строкой.
Остальные смысловые позиции Leader сохраняются, а карта Directory в
Leader/20–23 устанавливается в `4500`.

Подробный алгоритм обоих направлений приведён в
[Алгоритм двусторонней конвертации MARC РГБ](Алгоритм%20двусторонней%20конвертации%20MARC%20РГБ.md).
