## Что означают правила

| Правило | Человекочитаемое условие |
| --- | --- |
| `LD-02` | Некорректная вычисляемая длина Leader/00–04 либо запрещённый профилем РГБ код Leader/18 (`c`, `n`) или Leader/19 (`a`, `b`, `c`). См. [выдержку со стр. 19 PDF](#pdf-page-19). |
| `DR-E2` | Тег Directory должен состоять ровно из трёх цифр, трёх прописных или трёх строчных латинских букв. См. [структуру Directory со стр. 30 PDF](#pdf-page-30). |
| `DF-G2` | Поле данных должно иметь ровно два индикатора. См. [структуру поля данных со стр. 30 PDF](#pdf-page-30). |
| `DF-G3` | Поле данных должно содержать хотя бы одно подполе с односимвольным кодом. См. [структуру подполей со стр. 30 PDF](#pdf-page-30). |
| `IN-G3` | Каждый индикатор должен быть одним допустимым символом: строчной латинской буквой, цифрой, пробелом или `#` как экранным обозначением пробела. См. [структуру поля со стр. 30](#pdf-page-30) и [обозначение пробела со стр. 39 PDF](#pdf-page-39). |
| `VF-G5` | На уровне проверки поля обнаружен недопустимый код подполя: допускается одна строчная латинская буква или цифра. |
| `SF-G4` | То же повреждение зарегистрировано на уровне проверки подполя. Поэтому `VF-G5` и `SF-G4` образуют пары и увеличивают число срабатываний, но не число ошибочных записей. |

### Физическая стр. 19: ограничения Leader в схеме РГБ

Для экземпляра MARC-JSON профиль РГБ исключает следующие коды:

- Leader/18 (Descriptive cataloging form): `c`, `n`;
- Leader/19 (Multipart resource record level): `a`, `b`, `c`.

Поэтому их наличие в реальной записи даёт `LD-02`, даже если сам код имеет общую
семантику в MARC 21.

<a id="pdf-page-30"></a>

### Физическая стр. 30: структура MARC-записи и полей

MARC-запись представлена как последовательность из Leader, Directory и области переменных
полей:

- Leader занимает 24 байта;
- каждая статья Directory занимает 12 байт и состоит из трёхсимвольного тега,
  четырёх цифр длины поля и пяти цифр начальной позиции поля;
- контрольные поля `00X` содержат значение без индикаторов и подполей;
- остальные поля данных начинаются с двух односимвольных индикаторов;
- за индикаторами следуют подполя; каждое подполе состоит из разделителя, односимвольного
  кода и значения;
- в ISO 2709 разделитель подполя имеет код `0x1F`, конец поля — `0x1E`, конец записи — `0x1D`.

Из этой структуры непосредственно следуют проверки `DR-E2`, `DF-G2` и `DF-G3`. Например, байт
`0x1F`, ошибочно попавший в позицию индикатора, может преждевременно начать подполе и вызвать
несколько связанных срабатываний валидатора.

<a id="pdf-page-39"></a>

### Физическая стр. 39: `#` как обозначение пробела

В табличном описании MARC-полей символ `#` используется как видимое обозначение пустой
позиции индикатора. Это не буквальный байт исходной ISO 2709-записи: в байтовом потоке такой
индикатор представлен ASCII-пробелом (`0x20`).

Для проверки `IN-G3` это означает:

- пробел в исходной MARC-записи допустим;
- `#` можно принимать в текстовом/экранном представлении как эквивалент пробела;
- управляющие байты `0x01`, `0x1C`, `0x1F` и знак `;` не являются обозначениями пробела и не
  проходят проверку индикатора.
